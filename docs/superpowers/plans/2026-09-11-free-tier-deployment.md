# Free-Tier Deployment Implementation Plan (Phase 0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the working spine — schema, seeder, auth, session — on a live public URL where a visitor clicks "View the demo" and lands in a populated workspace that resets itself daily, all on free tiers.

**Architecture:** One Vercel project holding two services. The `frontend` service (Next.js) is the only one with a public rewrite; the `backend` service (FastAPI) is reachable only through a service binding that injects its URL as `API_BASE_URL`. Because bindings do not resolve in middleware, refresh rotation moves out of `src/proxy.ts` into a Route Handler, which may write cookies and may call the binding. A daily Vercel cron hits a frontend Route Handler that calls a guarded backend endpoint, which wipes and re-seeds the demo workspace's ledger in one transaction.

**Tech Stack:** Next.js 16.3.4 (App Router), React 19.2.8, Zod 4, FastAPI 0.121.2, SQLAlchemy 2.0.46, Alembic 1.17.2, pytest 8.4.2, Neon Postgres, Vercel Services (beta).

**Spec:** `docs/superpowers/specs/2026-09-11-free-tier-deployment-and-phases-3-6-design.md`

**Depends on:** `docs/superpowers/plans/2026-09-08-schema-views-and-seeder.md` and `docs/superpowers/plans/2026-09-09-auth-and-session.md`, both complete and merged. This plan changes no schema and adds no migration.

## Global Constraints

- **The backend service has no public rewrite.** The only top-level rewrite routes `/(.*)` to `frontend`. If FastAPI becomes reachable from a browser, the change is wrong.
- **`API_BASE_URL` is generated by the service binding.** Never set it by hand in the Vercel dashboard for the frontend service. `src/lib/api/client.ts:16` already reads it, with a `http://127.0.0.1:8000` fallback for local development.
- **Bindings resolve in functions only, never in middleware.** `src/proxy.ts` must not `fetch()` the backend after this plan.
- **The reseed endpoint operates only on `settings.demo_workspace_id`.** It never reads a workspace id from the request. Any parameter that could redirect it at another workspace is the bug this constraint exists to prevent.
- **`X-Admin-Token` is compared with `secrets.compare_digest`.** A `==` on a secret is a timing oracle.
- **The seeder stays deterministic.** `Rng(SEED)` with `SEED = 0x0001_9F0C` produces the same 460 invoices every run. Any change that alters the order in which `rng` is consumed changes the dataset and breaks the invariant tests.
- **Services own the transaction; repositories never commit.** Unchanged from plan 2.
- **Run backend commands from `backend/`** with the virtualenv active. `DATABASE_URL` must point at a database whose name contains `test` before running pytest — `backend/tests/conftest.py:24` refuses otherwise, and it downgrades to base before migrating.
- **Cookie flags are unchanged:** `httpOnly`, `secure` in production, `sameSite=lax`, `path=/`. `ip_at` lives 30 minutes, `ip_rt` 14 days.

```python
"""The demo reset.

The demo workspace is shared and writable, so it drifts: invoices marked paid,
reminders logged, customers added. A daily reset is what keeps it presentable.
Three properties make that safe, and each is asserted here:

* it produces the same ledger every time, so the demo a visitor sees in March
  is the demo a visitor saw in January;
* it keeps the workspace, its members and its email templates, so the demo
  login still works afterwards;
* it touches exactly one workspace.
"""

from __future__ import annotations

import uuid

from sqlalchemy import func, select
from sqlalchemy.orm import Session

from app.models.activity import CollectionEvent, EmailTemplate
from app.models.auth import WorkspaceMember
from app.models.invoicing import Customer, Invoice, InvoiceItem, Payment
from app.seeds.demo import reseed_demo_workspace, seed_demo_workspace


def invoice_fingerprint(db: Session, workspace_id: uuid.UUID) -> list[tuple[str, int, int]]:
    """Number, amount and paid amount for every invoice, in a stable order.

    A count alone would pass for a ledger reseeded with different numbers.
    """
    rows = db.execute(
        select(Invoice.number, Invoice.amount_cents, Invoice.paid_cents)
        .where(Invoice.workspace_id == workspace_id)
        .order_by(Invoice.number)
    ).all()
    return [tuple(row) for row in rows]


def test_reseed_reproduces_the_same_ledger(db: Session) -> None:
    workspace_id = seed_demo_workspace(db, owner_email="demo@example.com")
    db.flush()
    before = invoice_fingerprint(db, workspace_id)
    assert len(before) == 460

    reseed_demo_workspace(db, workspace_id)
    db.flush()

    assert invoice_fingerprint(db, workspace_id) == before


def test_reseed_clears_drift(db: Session) -> None:
    workspace_id = seed_demo_workspace(db, owner_email="demo@example.com")
    db.flush()

    stray = Customer(
        id=uuid.uuid4(),
        workspace_id=workspace_id,
        name="Visitor Added This",
        contact_name="Nobody",
        email="visitor@example.com",
        phone="+1 (555) 000-0000",
        industry="Other",
        payment_terms_days=30,
    )
    db.add(stray)
    db.flush()

    reseed_demo_workspace(db, workspace_id)
    db.flush()

    names = db.scalars(
        select(Customer.name).where(Customer.workspace_id == workspace_id)
    ).all()
    assert "Visitor Added This" not in names


def test_reseed_keeps_members_and_templates(db: Session) -> None:
    workspace_id = seed_demo_workspace(db, owner_email="demo@example.com")
    db.flush()

    reseed_demo_workspace(db, workspace_id)
    db.flush()

    members = db.scalar(
        select(func.count())
        .select_from(WorkspaceMember)
        .where(WorkspaceMember.workspace_id == workspace_id)
    )
    templates = db.scalar(
        select(func.count())
        .select_from(EmailTemplate)
        .where(EmailTemplate.workspace_id == workspace_id)
    )
    assert members == 1
    assert templates == 3


def test_reseed_touches_only_its_own_workspace(db: Session) -> None:
    demo_id = seed_demo_workspace(db, owner_email="demo@example.com")
    other_id = seed_demo_workspace(db, owner_email="real@example.com")
    db.flush()
    other_before = invoice_fingerprint(db, other_id)

    reseed_demo_workspace(db, demo_id)
    db.flush()

    assert invoice_fingerprint(db, other_id) == other_before


def test_reseed_leaves_no_orphaned_children(db: Session) -> None:
    workspace_id = seed_demo_workspace(db, owner_email="demo@example.com")
    db.flush()

    reseed_demo_workspace(db, workspace_id)
    db.flush()

    invoice_ids = set(

    )
    for model in (InvoiceItem, Payment, CollectionEvent):
        parents = db.scalars(
            select(model.invoice_id).where(model.workspace_id == workspace_id)
        ).all()
        assert set(parents) <= invoice_ids
```

```python
    """Create a complete demo workspace and return its id.

    Everything is inserted in one session and flushed, not committed -- the
    caller owns the transaction, which is what lets the tests roll it back.
    """
    workspace_id = uuid.uuid4()
    session.add(
        Workspace(
            id=workspace_id,
            name="Meridian Studio",
            slug=f"meridian-studio-{workspace_id.hex[:8]}",
            plan="professional",
            currency="USD",
        )
    )

    owner_id = uuid.uuid4()
    session.add(
        User(
            id=owner_id,
            email=owner_email,
            full_name="Alex Mercer",
            password_hash="",
        )
    )
    # None of these models declare an ORM relationship() back to Workspace or
    # User -- only a bare foreign-key column -- so the unit of work has no
    # signal to order INSERTs across tables/classes and a later flush can send
    # child rows before the parent. Flushing each parent immediately avoids it.
    session.flush()

        WorkspaceMember(
            id=uuid.uuid4(),
            workspace_id=workspace_id,
            user_id=owner_id,
            role="owner",
            status="active",
        )
```

```python
# Child tables before parents: Postgres rejects a DELETE that orphans a row,
# and the deletes here are statement-level, so the ORM's unit-of-work ordering
# does not apply.
LEDGER_TABLES = (
    CollectionEvent,
    CommunicationLog,
    AuditLog,
    ImportBatch,
    Payment,
    InvoiceItem,
    Invoice,
    Customer,
)


def reseed_demo_workspace(session: Session, workspace_id: uuid.UUID) -> None:
    """Replace one workspace's ledger with a fresh copy of the demo data.

    The workspace row, its members and its email templates are deliberately
    left alone. The caller owns the transaction: nothing here commits, so a
    failure part-way through leaves the old ledger intact rather than an empty
    workspace.
    """
    for model in LEDGER_TABLES:
        session.execute(delete(model).where(model.workspace_id == workspace_id))

    session.flush()
    populate_demo_ledger(session, workspace_id)
```

```python
from __future__ import annotations

import secrets
from typing import Annotated

from fastapi import APIRouter, Header, HTTPException, status
from sqlalchemy import func, select

from app.api.deps import SessionDep
from app.core.config import get_settings
from app.models.invoicing import Invoice
from app.seeds.demo import reseed_demo_workspace

router = APIRouter(prefix="/admin", tags=["Admin"])


@router.post("/reseed")
def create_reseed(
    session: SessionDep,
    x_admin_token: Annotated[str | None, Header()] = None,
) -> dict[str, object]:
    """Reset the demo workspace's ledger.

    Three guards, each sufficient on its own:

    1. This service has no public rewrite, so the endpoint is not reachable
       from the internet at all -- only over the service binding.
    2. ``X-Admin-Token`` must match a secret held only in this service's
       environment, compared in constant time.
    3. The workspace comes from configuration. No request may name one, so
       there is no code path by which this deletes a real user's data.
    """
    settings = get_settings()
    if settings.admin_token is None or settings.demo_workspace_id is None:
        # Unconfigured means the endpoint has no work it is allowed to do.
        # Answering 404 rather than 401 keeps it from advertising itself.
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Not found")

    if not secrets.compare_digest(x_admin_token or "", settings.admin_token):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="Not authenticated"
        )

    workspace_id = settings.demo_workspace_id
    reseed_demo_workspace(session, workspace_id)
    session.flush()

    invoice_count = session.scalar(
        select(func.count())
        .select_from(Invoice)
        .where(Invoice.workspace_id == workspace_id)
    )
    return {
        "status": "reseeded",
        "workspace_id": str(workspace_id),
        "invoice_count": invoice_count,
    }
```

## Task 5: Move refresh rotation out of the proxy

**Files:**
- Create: `src/app/api/session/refresh/route.ts`
- Modify: `src/proxy.ts:56-86` (the refresh branch), `:97-123` (`rotate`), `:125-129` (`config`)

**Interfaces:**
- Consumes: `ACCESS_COOKIE`, `REFRESH_COOKIE`, `REFRESH_MAX_AGE`, `sessionCookieOptions` from `@/lib/auth/cookies`.
- Produces: `GET /api/session/refresh?next=<path>` — rotates the pair, sets both cookies, redirects to `next`. Nothing imports it; the proxy redirects to it.

**Why this task exists.** On Vercel the backend has no public URL; `API_BASE_URL` comes from a service binding, and bindings do not resolve in middleware. The rotation `fetch()` at `src/proxy.ts:104` therefore cannot work in production. A Route Handler is a function, so the binding resolves, and it may write cookies.

**Two details that will cost an afternoon if missed:**

1. The proxy's matcher must exclude `/api/session/refresh`. Otherwise the redirected request arrives with no `ip_at`, the proxy redirects it to itself, and the browser reports a redirect loop.
2. `next` must be validated as a relative, same-origin path before it is used. A `next=https://evil.example` turns the handler into an open redirect.

- [ ] **Step 1: Write the route handler**

Create `src/app/api/session/refresh/route.ts`:

```ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

import {
  ACCESS_COOKIE,
  REFRESH_COOKIE,
  REFRESH_MAX_AGE,
  sessionCookieOptions,
} from "@/lib/auth/cookies";

/**
 * Refresh rotation.
 *
 * This lives in a Route Handler rather than in proxy.ts for one concrete
 * reason: on Vercel the backend has no public URL, and the binding that
 * provides API_BASE_URL does not resolve in middleware. A Route Handler is a
 * function, so it resolves there, and unlike a Server Component render it is
 * allowed to write cookies.
 *
 * proxy.ts redirects here when the access cookie is gone but the refresh
 * cookie is not. This handler either swaps the pair and sends the person back
 * where they were going, or clears both cookies and sends them to /login.
 */
export async function GET(request: NextRequest) {
  const next = safeNext(request.nextUrl.searchParams.get("next"));
  const refreshToken = request.cookies.get(REFRESH_COOKIE)?.value;

  if (!refreshToken) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  const rotated = await rotate(refreshToken);

  if (!rotated) {
    // Reused, revoked or expired. Clearing both cookies is what stops the next
    // navigation from retrying a rotation that cannot succeed.
    const failed = NextResponse.redirect(new URL("/login", request.url));
    failed.cookies.delete(ACCESS_COOKIE);
    failed.cookies.delete(REFRESH_COOKIE);
    return failed;
  }

  const response = NextResponse.redirect(new URL(next, request.url));
  response.cookies.set(
    ACCESS_COOKIE,
    rotated.access_token,
    sessionCookieOptions(rotated.expires_in),
  );
  response.cookies.set(
    REFRESH_COOKIE,
    rotated.refresh_token,
    sessionCookieOptions(REFRESH_MAX_AGE),
  );
  return response;
}

/**
 * `next` arrives in a query string, so it is attacker-controlled. Anything but
 * a single-slash-prefixed relative path is discarded: `//evil.example` and
 * `https://evil.example` are both absolute, and redirecting to either would
 * make this an open redirect.
 */
function safeNext(value: string | null): string {
  if (!value || !value.startsWith("/") || value.startsWith("//")) return "/dashboard";
  return value;
}

async function rotate(
  refreshToken: string,
): Promise<{ access_token: string; refresh_token: string; expires_in: number } | null> {
  try {
    const response = await fetch(
      `${process.env.API_BASE_URL ?? "http://127.0.0.1:8000"}/api/auth/refresh`,
      {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ refresh_token: refreshToken }),
        cache: "no-store",
      },
    );
    if (!response.ok) return null;
    const body = (await response.json()) as {
      tokens: { access_token: string; refresh_token: string; expires_in: number };
    };
    return body.tokens;
  } catch {
    // The backend being unreachable must not hard-fail the navigation.
    return null;
  }
}
```

## Task 8: The cron entry point

**Files:**
- Create: `src/app/api/cron/reseed/route.ts`

**Interfaces:**
- Consumes: `POST /api/admin/reseed` on the backend (Task 4), `process.env.API_BASE_URL` (the binding), `process.env.ADMIN_TOKEN`, `process.env.CRON_SECRET`.
- Produces: `GET /api/cron/reseed` — 200 with the backend's JSON on success, 401 on a bad secret, 502 when the backend refuses.

Vercel's scheduler sends `Authorization: Bearer $CRON_SECRET`. The same handler serves the GitHub Actions fallback named in the spec, which sends the identical header.

- [ ] **Step 1: Write the handler**

Create `src/app/api/cron/reseed/route.ts`:

```ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

/**
 * Daily demo reset.
 *
 * Vercel's scheduler calls this with `Authorization: Bearer $CRON_SECRET`.
 * The path is public — every cron path is, since the scheduler enters through
 * the same front door as everyone else — so the secret is the whole guard here,
 * and the backend checks its own X-Admin-Token behind that.
 */
export async function GET(request: NextRequest) {
  const secret = process.env.CRON_SECRET;
  const adminToken = process.env.ADMIN_TOKEN;

  if (!secret || request.headers.get("authorization") !== `Bearer ${secret}`) {
    return NextResponse.json({ error: "Not authenticated" }, { status: 401 });
  }

  if (!adminToken) {
    return NextResponse.json({ error: "Not configured" }, { status: 500 });
  }

  const response = await fetch(
    `${process.env.API_BASE_URL ?? "http://127.0.0.1:8000"}/api/admin/reseed`,
    {
      method: "POST",
      headers: { "X-Admin-Token": adminToken },
      cache: "no-store",
    },
  );

  if (!response.ok) {
    // Surfaced rather than swallowed: a reset that silently stops working is
    // how the demo ends up showing a year of visitor edits.
    return NextResponse.json(
      { error: "Reseed failed", status: response.status },
      { status: 502 },
    );
  }

  return NextResponse.json(await response.json());
}
```

- [ ] **Step 2: Typecheck and build**

Expected: both succeed.

